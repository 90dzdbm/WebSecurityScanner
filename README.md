# Web 安全测试工具

一个基于 Python 标准库（tkinter）的图形化 Web 安全测试工具，用于**已获得授权的**本地测试环境。扫描逻辑在后台线程执行，界面实时显示日志与进度，扫描结束后生成带风险等级的中文文本报告。

> ⚠️ **仅限授权测试。** 请只对自己拥有管理权限或已获得明确书面授权的目标使用本工具。未经授权扫描第三方系统可能违反法律法规。

---

## 一、功能概览

按顺序执行五个阶段，每个阶段都会在日志区输出结果并更新进度条：

| 阶段 | 内容 |
| --- | --- |
| 1. 信息收集 | 请求首页，提取状态码、响应头、Server / X-Powered-By、页面标题、链接和表单，检查缺失的安全响应头 |
| 2. 端口扫描 | 按所选强度档位的端口列表做 TCP 连接检测（只建立连接，不发送应用层数据） |
| 3. 目录探测 | 按强度档位的路径字典并发探测，自动过滤软 404，敏感路径标记风险 |
| 4. 表单漏洞检测 | 对首页发现的表单使用无害 payload（`'` 与 `<script>alert(1)</script>`）检测 SQL 注入报错特征和 XSS 反射迹象，只记录异常响应，不提取数据 |
| 5. 报告输出 | 汇总为文本报告，弹出预览窗口，可保存为 `.txt` 文件 |

其他特性：

- 开始扫描前必须通过**授权确认对话框**（勾选“我确认拥有该目标的测试授权”后才可点击“确认开始”）。
- 支持**停止扫描**：点击后设置停止标志，后台线程在下一个检查点安全退出，并记录“扫描已停止”。
- 日志带时间戳，按“信息 / 警告 / 风险 / 系统”分色显示。
- 强度档位提供低 / 中 / 高三档，也可选择“自定义”，在界面内自行设置请求间隔、并发线程数、超时、重试次数、路径字典与端口列表。
- 支持**持续扫描**：勾选后每一轮五阶段扫描结束会自动开始下一轮，直到点击“停止扫描”才结束，并把各轮结果汇总为一份报告。
- 支持**超强力扫描**：勾选后开始扫描时按指定数量打开相同参数的独立扫描器子窗口并自动开扫；数量由用户输入、无上限，支持“一键打开 / 一键关闭”。
- 支持**有害化攻击模式**：追加时间盲注、命令注入回显、扩展 SQLi/XSS 等激进探针（保持非破坏性），报告单独标注检测模式。
- 所有请求都设置了**超时**和**有限重试**；并发线程数不再限制为 5，可在“自定义”档位中自由设置（上限 200，仅用于防止误填超大数值）。
- 不发送破坏性 payload，不做暴力破解。

## 四、打包为单个 exe（可选）

程序不打包也能直接运行（`python main.py`）。如果需要分发给没有 Python 环境的机器，可在项目根目录（`main.py` 所在目录）执行：

```bash
pip install pyinstaller
pyinstaller --onefile --windowed --name WebSecurityScanner main.py
```

- `--onefile`：打包为单个可执行文件；
- `--windowed`：不显示控制台窗口（GUI 程序）；
- 生成的程序位于 `dist\WebSecurityScanner.exe`，可复制到没有 Python 环境的 Windows 机器上双击运行。

可选：加图标（准备 `.ico` 文件）：

```bash
pyinstaller --onefile --windowed --name WebSecurityScanner --icon app.ico main.py
```

> 首次启动 exe 时，部分杀毒软件可能对 PyInstaller 打包程序做额外检查，这是打包工具的常见现象；可对生成文件做哈希校验或加入信任列表。
>
> 注意：`--onefile` 启动时需要向 `%TEMP%` 解包运行时文件，因此该目录必须可写（可用空间也要足够）。若系统或安全软件限制临时目录写入，会看到 `Failed to extract ...` 之类的报错，此时可改用 `--onedir` 打包，或直接以 `python main.py` 运行。

## 五、强度档位参数（`websectool/config.py`）

所有扫描参数集中在 `INTENSITY_LEVELS` 字典中，扫描函数只从该字典读取，便于按需修改：

| 参数 | 低强度（隐蔽） | 中强度（默认） | 高强度（快速） |
| --- | --- | --- | --- |
| 请求间隔 | 1.0 s | 0.3 s | 0.05 s |
| 线程数 | 1 | 2 | 5 |
| 路径字典 | 10 条 | 30 条 | 60 条 |
| 请求超时 | 5 s | 3 s | 2 s |
| 端口列表 | 80, 443 | 80, 443, 8080, 8443 | 常见 10 个 Web 端口 |
| 单次重试 | 2 | 1 | 1 |
| 最大表单数 | 4 | 6 | 8 |
| 每表单最多测字段 | 4 | 5 | 5 |

说明：

- 线程数不再做 5 线程的安全限制：按所选档位或自定义值直接使用，仅保留 `THREADS_LIMIT = 200` 作为误填保护。
- 想增减探测路径，直接编辑对应档位的 `paths` 列表；端口同理修改 `ports`。
- 想调整界面默认档位，修改 `DEFAULT_INTENSITY`。

### 自定义档位（界面内修改，无需改代码）

在强度下拉框中选择“自定义”后，右侧的“自定义参数…”按钮变为可用，点击后可在对话框中填写：

| 参数 | 允许范围 | 说明 |
| --- | --- | --- |
| 请求间隔（秒） | 0 ~ 10 | 相邻请求之间的等待时间 |
| 并发线程数 | 1 ~ 200 | 上限为 `THREADS_LIMIT`，仅防止误填超大数值，不再限制为 5 |
| 请求超时（秒） | 0.5 ~ 60 | 单次请求超时 |
| 重试次数 | 0 ~ 5 | 请求失败后的额外重试次数 |
| 最多测试表单数 | 1 ~ 50 | 表单检测阶段最多处理多少个表单 |
| 每表单最多字段数 | 1 ~ 30 | 每个表单最多测试多少个输入字段 |
| 端口列表 | 1 ~ 200 个（1-65535） | 支持逗号、分号、空格、换行分隔，自动去重 |
| 路径字典 | 1 ~ 500 条 | 每行一条，`#` 开头为注释行，缺少开头 `/` 会自动补全 |

对话框行为：

- 点击“确定”时先调用 `normalize_custom_config()` 校验；参数越界或格式错误会弹出中文提示且不会关闭窗口；
- “恢复默认”会填回 `DEFAULT_CUSTOM_CONFIG`（与“中强度”一致）；
- 校验通过后配置保存在界面中，扫描日志与报告中都会标注“自定义”以及 `参数来源   ：用户自定义`。

### 持续扫描模式

在主界面勾选“**持续扫描（循环执行，直到点击“停止扫描”）**”后点击“开始扫描”，扫描逻辑会在后台线程中**循环执行**：

- 每一轮仍然按“信息收集 → 端口扫描 → 目录探测 → 表单漏洞检测 → 报告输出”五个阶段执行；
- 日志与状态栏中的阶段名会带上轮次前缀，例如“第 2 轮 · 目录探测”；
- 每轮结束后停顿 `max(1 秒, 请求间隔 × 2)`，随后自动开始下一轮；
- 只有点击“停止扫描”（或关闭窗口）才会结束，停止时仍会把已完成各轮的结果写入报告；
- 持续扫描的报告标题为“Web 安全测试报告（持续扫描）”，除各轮详细报告外还包含：

| 字段 | 说明 |
| --- | --- |
| 扫描模式 | 持续扫描（循环执行，直到用户主动停止） |
| 完成轮次 | 实际完成的完整轮数 |
| 扫描状态 | 已停止（由用户主动停止）/ 完成 |
| 累计用时 | 从第一轮开始到停止的总时长 |
| 累计风险 | 各轮高风险 / 中风险 / 低风险项数合计（未去重，便于发现重复出现的风险） |

> 持续扫描同样受“授权确认”约束；停止按钮在扫描期间始终可用，用于结束循环。

### 超强力扫描模式

主界面新增“**超强力扫描**”一行，包含：复选框、`窗口数量` 输入框、“一键打开”“一键关闭”按钮和子窗口运行计数。

- **开始扫描时**：勾选“超强力扫描”后点击“开始扫描”，主窗口照常扫描，同时按输入数量启动 N 个独立的扫描器子窗口进程；子窗口继承主窗口的全部扫描参数（目标 URL、强度档位、自定义参数、持续扫描开关）并**自动开始扫描**，无需再确认授权（授权已由主窗口完成）。
- **一键打开**：随时按当前参数批量打开指定数量的子扫描窗口。主窗口空闲时会先弹出授权确认；正在扫描时直接继承当前参数。
- **一键关闭**：终止本窗口打开的全部子扫描窗口进程。
- **窗口数量**：由用户输入，**无上限**（只要求是不小于 1 的整数）。
- **联动停止**：点击“停止扫描”或关闭主窗口时，会同步关闭全部子窗口，避免留下无人管理的扫描进程。
- **自动隐藏**：子窗口开始扫描后会**自动最小化到任务栏**，避免遮挡主窗口；扫描结束时会自动恢复显示报告，也可随时从任务栏点开查看实时日志。
- **防无限派生**：子窗口标题带“（超强力扫描窗口）”后缀，自身不再显示“超强力扫描”行，不能继续派生孙窗口。

实现方式：子窗口通过命令行参数 `--child-scan=<base64(json)>` 接收参数（`gui.parse_argv()` 解析），用 `subprocess.Popen` 再次启动程序本身（打包后为 exe，源码运行为 `pythonw.exe main.py`）。

> ⚠️ 提示：N 个子窗口意味着约 N 倍的请求速率与资源占用，请仅在授权范围内、目标可承受时使用，并优先配合较大的请求间隔。

### 有害化攻击模式（激进检测）

在主界面勾选“**有害化攻击模式**”后，表单检测阶段会在默认无害 payload 之外追加更具攻击性的探针：

| 探针类别 | 内容 | 判定方式 |
| --- | --- | --- |
| 扩展 SQLi | `'`、`"`、`')`、`";`、`1' AND '1'='1`、`1' AND '1'='2` | 响应中新出现数据库报错特征，或服务端 500 |
| 时间盲注 | `SLEEP(3)`、`WAITFOR DELAY '0:0:3'`、`pg_sleep(3)` | 单次响应比基线慢约 2 秒以上且达到 2.4 秒阈值 |
| 命令注入回显 | `;echo WST_CMD_OK`、`|echo ...`、`$(echo ...)` | 剔除“整段输入被反射”的情况后，响应中仍出现固定标记 |
| 扩展 XSS | `<script>`、`<img onerror>`、`"><svg onload>` 等 | payload 被原样反射且基线中不存在 |

要点：

- 勾选时会弹出**二次确认**，说明探针内容与可能的 WAF/IDS 告警；
- 所有探针保持**非破坏性**：不删改数据、不写文件、不反弹 shell、不做暴力破解；
- 报告中会额外标注 `检测模式   ：有害化攻击模式（激进探针…）`，日志区同步给出警告；
- 探针同样遵循所选档位的请求间隔、超时、重试与停止标志；扫描中该开关会被锁定。

> 时间盲注每字段每轮约多消耗 3 秒（`SLEEP`/`WAITFOR` 探针各一次），建议在“自定义”档位里适当调大超时。
>
> ⚠️ 激进探针可能触发目标侧防护告警，请仅在获得明确授权的测试环境中使用。

## 六、使用步骤

1. 双击运行程序（或 `python main.py`）。
2. 在“目标 URL”输入框填写地址。可以不带协议前缀，例如 `127.0.0.1:8080`，程序会自动补全为 `http://127.0.0.1:8080`。
3. 选择扫描强度（默认“中强度”）。如需自行设定参数，选择“自定义”，再点击右侧“自定义参数…”按钮填写并校验。
4. 如需让扫描循环执行，勾选“持续扫描（循环执行，直到点击“停止扫描”）”；不勾选则只扫描一轮。
5. 如需并行多开扫描窗口，勾选“超强力扫描”并填写窗口数量（无上限）；也可随时用“一键打开 / 一键关闭”控制子窗口。
6. 如需启用激进探针，勾选“有害化攻击模式”并在二次确认中确认。
7. 点击“开始扫描”。
8. 在授权确认对话框中阅读提示，勾选“我确认拥有该目标的测试授权”后点击“确认开始”。
9. 观察日志与进度条；需要中止时点击“停止扫描”（持续扫描模式下必须点击它才会结束；子窗口会同步关闭）。
10. 扫描结束后在报告预览窗口查看结果，点击“保存报告”保存为 `.txt` 文件。

### 输入校验

`websectool/gui.py` 中的 `normalize_target()` 与 `get_user_input_and_validate()` 负责输入处理：

- 空输入、含空格、缺少主机名、端口非法、非 http/https 协议都会给出中文提示；
- 缺少 `http://` / `https://` 前缀时自动补全 `http://`；
- 校验通过后才进入授权确认并启动扫描。

## 七、安全边界与实现说明

- **授权确认**：每次扫描前强制弹出确认框，未勾选授权无法开始；超强力扫描的子窗口继承主窗口已确认的授权，且自身不能继续派生子窗口。
- **请求约束**：所有 HTTP 请求均有超时与重试上限；失败重试使用可中断的退避等待。
- **并发线程数**：不再做 5 线程的安全限制，按档位或自定义值直接使用；仅保留 `THREADS_LIMIT = 200` 作为误填保护。
- **表单范围**：只测试与目标同主机的表单，避免向第三方系统发送请求。
- **无害 payload**：默认仅使用单引号与 `<script>alert(1)</script>` 做迹象判断，不执行脚本、不导出数据、不做盲注或时间盲注；只有显式开启“有害化攻击模式”后才会追加时间盲注/命令注入回显等激进探针，且探针保持非破坏性。
- **响应大小**：单次响应最多读取 2 MB，避免超大页面拖垮程序。
- **TLS 证书**：测试环境常用自签名证书，因此默认不校验证书（`scanner.py` 中的 `_SSL_CONTEXT`）。如需严格校验，改回 `ssl.create_default_context()` 即可。
- **报告内容**：报告包含目标、强度、参数、各阶段结果与风险汇总，不包含 Cookie 值等敏感凭据。

### 线程与界面刷新

- 扫描在 `threading.Thread(daemon=True)` 中执行；
- 后台线程通过 `queue.Queue` 发送 `("log", 级别, 文本)`、`("progress", 数值)`、`("stage", 名称)`、`("done", 报告, 是否停止)`；
- 主线程每 80 ms 轮询一次队列，所有 tkinter 控件操作都发生在主线程；
- 停止标志为 `threading.Event`，扫描各阶段的检查点和请求间隔等待都会响应它。

## 九、常见问题

**Q：扫描报告里没有发现漏洞，是否代表目标安全？**
不是。本工具只做初步的、无害的迹象检查，覆盖范围有限，结果不能作为安全结论。

**Q：为什么目录探测有一些 403 路径？**
路径存在但被访问控制拦截，工具会以“警告”级别记录，便于进一步人工确认。

**Q：扫描时界面是否卡顿？**
扫描在后台线程执行，界面只负责消费队列消息。若目标响应很慢，停止操作会在当前请求超时后生效。

**Q：能否扫描 https 自签名站点？**
可以。默认跳过证书校验，但请确认目标属于您的授权范围。
